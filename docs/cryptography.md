# Cryptographic foundation

P13 supplies outbound adapter primitives, not authentication or delivery flows. `Secrets` issues 32-byte random base64url tokens and SHA-256 token hashes. Its AES-256-GCM envelopes use a fresh 12-byte nonce, 128-bit authentication tag and authenticated key ID. Key IDs are 1–64 ASCII letters/digits/underscore/hyphen. A key file contains exactly 32 raw bytes; reads are bounded and reject final-component symbolic links. The loader clears temporary key bytes after the JCE key copies them. Mount private read-only key files inside protected directories; never commit them. Use independent keys and instances for TOTP storage and authentication delivery. Keep key IDs and corresponding recovery keys available while their data remains needed; this primitive accepts only its configured ID and performs no automatic rotation or fallback.

Plaintext is limited to 65536 UTF-8 bytes, envelopes to 87500 characters. Null/malformed/truncated/oversized/authentication failures return fixed safe diagnostic codes, without plaintext, path, envelope or provider cause. No primitive logs values. Java immutable strings and JCE internal key copies cannot be reliably erased; keep plaintext lifetimes short. Buffer clearing reduces temporary copies rather than promising complete process-memory erasure.

`Totp` generates 20-byte secrets and verifies six ASCII digits with HMAC-SHA1 and 30-second steps, accepting only the adjacent previous/current/next step and steps newer than the caller's last accepted step. It returns the accepted step or -1. The P16 identity transaction must lock the administrator record and atomically persist that step before issuing authenticated access. This helper alone is not durable replay prevention. Callers own and must clear returned secret arrays. Private enrollment, encryption, recovery, throttling and sessions belong to their identity tasks.

Argon2 is currently a test-scoped implementation proof: RFC9106 Argon2id v1.3 section5.3 plus the approved 65536KiB/3-iteration/one-lane baseline. Password encoding, random production salts and protected hash storage are P16 work. The synthetic timing receipt contains only parameters and elapsed nanoseconds; it is not a latency gate or production-capacity claim.

Tests use all 18 SHA1/SHA256/SHA512 [RFC6238 Appendix B](https://www.rfc-editor.org/rfc/rfc6238#appendix-B) vectors, [RFC9106 section5.3](https://www.rfc-editor.org/rfc/rfc9106#section-5.3), public SHA256 fixtures and synthetic values. Generated tokens, secret keys, plaintext and password-derived bytes are compared through boolean assertions so assertion reports cannot echo them. Failures include only fixed diagnostic codes. Key files live under JUnit temporary directories and are removed by JUnit. Run `bash scripts/ci/verify-build.sh`; adapters independently require 90% lines and branches, with missing source/report checks enforced.
