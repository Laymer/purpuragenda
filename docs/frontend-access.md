# Shared frontend access

`SessionAccess` holds only a server-issued CSRF proof and public role/deadline snapshot in memory. `bootstrap()` coalesces overlapping refreshes. Every `perform()` operation and explicit refresh shares a serial queue so authentication cannot rotate the proof between another request's preparation and transmission. Generated authentication clients run inside `authenticate`, which consumes the SessionBootstrap reply and returns only public context. Uncertain authentication rotation invalidates the context rather than retaining a possibly stale proof. Requests have a25-second bound; cancellation by navigation does not implicitly retry a command.

Idle/absolute expiry equality, logout completion including uncertainty, revocation/CSRF rejection and failed bootstrap invalidate the context and prepared commands. Successful authentication or an explicit refresh also starts a new privacy generation, so earlier intents never cross identities, including a cookie changed in another tab. A known AUTHENTICATION_FAILED response retains the unchanged valid context. Epoch checks refuse late responses and work queued under an invalid context. Public invalidation listeners let views clear intake and other private state; callbacks must not persist or log borrowed proofs. The context does not poll or extend idle life, and does not create administrator authority. Cookie handling remains browser/server-owned.

`CommandAccess.prepare(method,path,body,version?)` freezes the exact JSON body, fresh idempotency key and optional strong numeric If-Match value before submission. It accepts only local API mutation paths. `attempt()` coalesces concurrent callers and sends once. A network timeout, transport/5xx failure or successful-status parsing failure is uncertain: the caller may explicitly retry the same object, retaining its identity, or discard it. Editing the form requires a new prepared command. There is no automatic mutation retry, and429 Retry-After prevents an early retry of the same command. A successful result is returned from memory on repeat calls without another request.

`discard()` clears retained submission/result material, blocks queued transmission and refuses late results. Session invalidation discards all registered commands. Safe failure kinds carry status and validated cooldown only; provider bodies, cookies, password/TOTP fields and arbitrary exception messages never enter them. Instances serialize to redacted labels. The final server transaction remains authoritative for ownership, expiry, versions, quota and overlap.

This foundation does not add booking/authentication screens or fake submission routes. P24/P25 and account/administrator views must use it rather than duplicate proof/command plumbing. Public catalog selection remains independent. Real workflow/browser acceptance and all local/hosted gates remain required for each consumer.
