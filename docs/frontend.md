# Angular shell

The P12 shell is an English standalone Angular22.2.3 application with Material22.2.4, system fonts and a local purple theme. Home and not-found routes are implemented; the keyboard skip link targets the main landmark and the not-found action returns home. Booking, account and administrator flows are introduced by their feature tasks. The shell has no links to unavailable features and performs no startup API request. No external scripts, fonts, trackers or persistent intake storage are introduced.

`appConfig` provides the router, HttpClient and the generated API's relative `/api/v1` base. SDK tests compile its complete export surface, use Angular HttpTestingController and verify catalog/query requests and typed HTTP failures without reaching a real backend. Same-origin HTTP sends cookies under browser rules without enabling cross-origin credentials. The public SDK remains generated from the P12 contract; do not edit its sources. Contract regeneration checks remain mandatory.

## Run and verify

Use the pinned toolchain, then run `bash scripts/ci/verify-frontend.sh`. It safely removes old coverage/build artifacts using directory descriptors anchored to the repository, refusing a symlinked frontend or artifact root, performs `npm ci`, runs all Angular tests and builds the production bundle. `npm --prefix frontend start` serves only loopback and proxies `/api` to the configured local backend. The full `bash scripts/ci/verify-build.sh` runs the frontend category before Maven and then the shared backend/frontend coverage check. Every PR, including documentation changes, therefore requires real Angular install/test/build evidence. Missing dependencies or commands fail; no fallback report or placeholder bundle is accepted.

Vitest5.0.5, coverage-v8 5.0.5 and the Vite8.3.3 override retain the reviewed patched pins. Dependencies are exact-versioned with an npm lockfile and package integrity hashes; `npm ci` verifies their agreement. The lockfile is generated content, separate from handwritten shell changes. Browser compatibility/accessibility/performance acceptance remains P39/P41; JSDOM component tests are not real-browser certification.

JUnit output must exist at `frontend/coverage/junit.xml`, contain a nonempty suite and executed cases with matching per-suite/root counts, and contain no failures/errors/skips. Production output must contain `index.html` and a hashed main bundle. The strict report checker reuses the shared source-complete coverage validator. All handwritten TypeScript under `frontend/src`, including application config, route components and bootstrap success/failure handling, requires90% lines and90% branches. Only specs/declarations and individual generated paths listed in generator provenance are excluded. Angular's coverage directory is explicitly set to `coverage` and JSON output produces `coverage-final.json`. Omitted source files cannot pass the independent coverage check even if the runner configuration excludes them.

All test inputs are synthetic. Startup failures display a fixed reload message and suppress internal errors. No tokens, credentials or personal data belong in test reports. Build/cache/reports remain ignored local artifacts.
