# Durable notification queue foundation

P14/queue-foundation provides a framework-free lease port and a JDBC queue adapter. It does not expand booking events, construct email content, decrypt authentication envelopes or send SMTP. Those are later P14/P36 slices; this foundation does not complete P14 or authorize live mail. Network work must begin only after `claim()` commits and must never run under a queue transaction or scheduling resource lock.

A claim checks restore suppression, sets READ COMMITTED explicitly and captures authoritative database time, reclaims up to100 expired/malformed leases, and selects a due queued row with `FOR UPDATE SKIP LOCKED`. It then takes a nonblocking transaction advisory lock for the booking/audience group and rechecks existing leases in a fresh statement. The existing003 exclusion constraint independently prevents simultaneous leased rows for one booking/audience. No applied migration is changed. Queued work in a leased group waits; unrelated bookings/audiences can progress. Authentication rows use challenge/audience grouping until the separate authentication-enqueue/preparation slice defines its recipient lifecycle; this is not a claim of recipient-wide authentication serialization.

The committed60-second lease contains a random token. `Lease.toString()` redacts that token. Lease IDs/deadlines are advisory to callers; renewal and completion reload and lock the actual database row, then capture database time. An expired lease, wrong token or terminal job cannot be renewed/completed/failed. Equality is expired. Restart/reclamation replaces the token, so a delayed former worker cannot overwrite the new lease or create a phantom delivery attempt. Per-statement5-second and lock2-second timeouts bound storage waits. Storage exceptions expose only `NOTIFICATION_STORAGE_FAILED`, without provider details, causes or suppressed errors.

Renewal also checks process/global delivery suppression. Successful completion removes the encrypted envelope and records one fenced attempt in the same transaction. Failures use fixed `SMTP_DELIVERY_FAILED`, with retries after1m/5m/30m/2h/6h/12h and terminal failure after the seventh failed claim. `due_at` is the next-attempt time; later reminder work must retain its original scheduled deadline separately for grace checks. Nothing in a lease makes SMTP exactly once: a crash after external acceptance can still cause a duplicate, which the later sender must document and mitigate with a stable Message-ID.

## Required verification

The outbox foundation category is implemented under the mandatory build job. `check-queue-report.py` requires the exact real PostgreSQL class, at least ten executed test cases, matching counts, and zero failures/errors/skips. Generic adapter/unit tests cannot replace this suite. Source activation/inventory and per-module coverage remain mandatory. The P07 PostgreSQL fixture is reused through composition, with the shared JUnit resource lock retained for future parallel execution.

Real database scenarios cover20 independent workers for different jobs in one booking/audience; different audience/booking progress; a locked row and held advisory group lock; restart renewal; expiry/token rotation and stale completion; durable retry timing/terminal failure; restore suppression and missing control; malformed old leases; a datasource defaulting to REPEATABLE READ, and a pg_stat_activity-confirmed row-lock wait extending past expiry. Pure application tests check inclusive expiry and redacted diagnostics. Storage-failure tests require fixed cause-free errors. Every fixture is synthetic; token comparisons are boolean and no provider error or token enters a report.

Run `bash scripts/ci/verify-build.sh`. Missing Docker/PostgreSQL must fail rather than skip. Local compilation and unit evidence do not certify real queue integrity or adapter coverage; exact-head container CI must provide that evidence before merge. The next P14 slice adds SMTP capture-only tests, protected encrypted auth preparation/expiry, stable Message-ID and a worker that performs all network I/O outside database transactions. Booking audience expansion and reminders remain P36.
