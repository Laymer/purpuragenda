# Administrator booking read model

P22's bounded read prerequisite exposes application/adapter ports only. Administrator HTTP, creation/change/configuration APIs and their workflow UI remain separate work; this document does not claim those routes exist.

`AdministratorBookingView.agenda` accepts inclusive Europe/Brussels civil dates, at most31 dates, and pages of1–100 entries. Midnight conversion follows Brussels DST, so one civil day can span23 or25 elapsed hours. The adapter uses a half-open instant range and orders by start instant then booking UUID. Its optional cursor advances strictly past that pair; the next cursor exists only when another row was observed. Each page is a fresh consistent snapshot, so concurrent insertions or rescheduling can change later pages. All booking states remain visible; expired pending holds are not mutated by a read.

Agenda rows contain only booking ID/reference/version/state, start, actual session end and immutable service name. They omit intake, contact data, customer identifiers, meeting links and payment references. Owner detail returns the original booking snapshot, current delivery contact/meeting/state and independent payment/refund facts for explicit private HTTP mapping later. Approval remains independent of payment.

Both reads independently validate the persisted session UUID/browser binding, ADMIN kind, enabled/enrolled administrator, matching security epoch, issued/authenticated timestamps, fifteen-minute idle deadline, eight-hour absolute deadline and revocation. Missing/invalid administrator authority fails before booking lookup; unknown booking IDs return no detail only after authorization. Ordinary reads use the live MFA session; no approved rule explicitly adds a detail-only ten-minute step-up. Existing sensitive mutation commands keep their established fresh-authentication requirement.

Each call starts an independent PostgreSQL read-only REPEATABLE READ transaction, captures database time once, and reads authority and data in that snapshot. A revocation committed before the snapshot denies access; an in-flight read can finish consistently with its earlier authorized snapshot. The query never locks scheduling/authority rows, touches sessions, expires holds or writes audit/outbox/receipts. No transport runs in its transaction. Provider errors expose only the safe STORAGE_FAILURE kind, and all new private projection containers redact toString.
