# Purpuragenda version 1 implementation plan

Approved baseline: 24 October 2026. Source: the full implementation plan supplied in the implementation request. This repository record preserves its requirements, decision register and gates. Actual implementation evidence belongs in status.md; a requirement in this document is not a claim of completion.

## Outcome and exclusions

English private Zoom consultation booking for Medina. One shared practitioner, one independent owner administrator, guest booking after email proof, optional explicitly enrolled accounts, PostgreSQL persistence, administrator approval or verified external-payment confirmation, durable notifications and calendar exports.

Seed Karmic reading: 30 minutes, EUR 15.00; Transit reading: 60 minutes, EUR 30.00. Both reserve exactly 120 elapsed minutes. Online checkout, automatic Zoom creation, two-way calendar sync, multiple practitioners/businesses, groups, recurring bookings, packages, discounts, waitlists, SMS, bans and astrological calculations are excluded.

## Architecture

Java 25/Maven/Spring Boot/PostgreSQL/Liquibase/Angular Material. Six Maven modules: domain, application, adapters, bootstrap, acceptance-tests, quality. Pure JDK domain; framework-free application use cases and inward-declared ports; explicit JDBC adapters; Spring composition in bootstrap. REST controllers call application use cases, never JDBC. OpenAPI 3.1 contract. Angular is advisory: final ownership, price, eligibility and capacity decisions are server-side.

SchedulingUnitOfWork uses TransactionTemplate, resource lock and transaction-scoped authoritative database time. All scheduling, expiry, settings and confirming-financial mutations use one lock order. No network operations under booking locks. PostgreSQL exclusion constraint protects half-open 120-minute resource occupancy independently of application code. Unexpected errors roll back; expected business errors can preserve expiry reclamation and durable idempotency receipts through savepoints.

## States, payment and effects

PENDING_CONFIRMATION -> CONFIRMED/REJECTED/EXPIRED/CANCELLED. CONFIRMED -> CANCELLED/COMPLETED/NO_SHOW. Terminal bookings never revive. Manual approval requires live future hold and unique validated participant Zoom URL; approval leaves payment unchanged. External receipt is immutable actual money, independently valid even after expiry/cancellation. Sufficient net EUR plus live hold plus meeting can confirm with EXTERNAL_PAYMENT basis. Receipt without meeting remains pending with original expiry. Financial projection UNPAID/PAID_EXTERNAL/REFUND_DUE/REFUNDED_EXTERNAL with received/refunded/due/remaining amounts; partial receipts stay unpaid; outstanding refund takes precedence. Duplicate references/keys never duplicate money. Late receipts create reconciliation, not occupancy. Provider cancellation refunds regardless cutoff; eligible customer cancellation refunds; admin-recorded late customer cancellation is explicitly classified and has no policy refund of existing money. Refunds link actual receipts and cannot exceed balance. Rejection/expiry release occupancy and create refund follow-up for receipts. Completion/no-show retain daily capacity and full occupancy. Rescheduling retains money and snapshots and notifies both audiences. Meeting changes increment confirmed calendar revisions. Every administrative change/override is audited; no automatic customer outcome email or ban.
